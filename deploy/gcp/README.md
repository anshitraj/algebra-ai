# Algebra on Google Cloud (one VM, behind Cloudflare)

How the API runs in production since 2026-10-22, when it left Railway after Railway disclosed that
customers' environment variables may have been read. The design goal: **no secret lives in a hosting
dashboard**, and a leak of the VM's configuration alone gives an attacker nothing usable.

```
 visitor ──► Cloudflare (DNS, TLS, DDoS, WAF) ──► tunnel (outbound only) ──► VM: API 127.0.0.1:8080
                                                                              │   Postgres 16 and Redis, localhost only
 web app (Vercel) ──► https://api.usealgebra.xyz  (same path)                 │   demo sellers 127.0.0.1:8402
                                                                              └─ reads its secrets with its own Google identity
```

| What | Where |
|---|---|
| Project | `algebra-prod-7802b5` (own project: no key, role or workload is shared with any other) |
| VM | `algebra-1`, e2-standard-4 (4 vCPU, 16 GB), Debian 12, Mumbai (`asia-south1-b`), shielded boot, deletion protection. It started as e2-medium and was upsized on 2026-10-22: the stack used about 0.7 GB, so this is headroom (and room to host the web app here later), not need |
| Reaching it | `gcloud compute ssh algebra-1 --tunnel-through-iap` (your Google login). SSH is reachable only through Google's IAP range. Since 2026-10-30 ports 80 and 443 are also open for Caddy (see "Public HTTPS without Cloudflare"); nothing else is |
| Secrets | Secret Manager, read by the VM's service account only; the master key is stored **wrapped by Cloud KMS** and unwrapped at start |
| Backups | nightly `pg_dump` to a private bucket; the VM can only add objects; each is kept 14 days (a compromised VM can't erase them), deleted after 45 |
| Logs and metrics | Google Ops Agent to Cloud Logging and Monitoring |
| Updates | `unattended-upgrades` (security), reboot at 03:00 India time only if one needs it |
| Cost | about 125 USD a month (about 10,500 INR): VM about 115, disk 3, external address 3.7, the rest pennies (estimates, not quotes: read the billing report). Budget alert at 15,000 INR with mails at 50, 90 and 100 percent |

## How a secret reaches the API

`algebra-api.service` runs `algebra-fetch-secrets` as root just before the API starts. It asks the
metadata server for the VM's token, reads each secret, asks KMS to unwrap the master key, and writes
`/run/algebra/api.env` (memory only, `root:algebra` 0640). `algebra-api-start` then loads it with
`/etc/algebra/api.conf` (the settings that are not secret) and starts the API. Nothing secret is on the
disk, in an image, or in this repository. To change a secret: add a new version, then
`sudo systemctl restart algebra-api` (and `cloudflared` for the tunnel token).

| Secret | Who sets it |
|---|---|
| `algebra-master-key-wrapped`, `algebra-db-password`, `algebra-redis-password`, `algebra-edge-secret`, `algebra-operator-token` | generated by `provision.sh`; never printed |
| `algebra-resend-api-key` | a person: the key from Resend |
| `algebra-cloudflare-tunnel-token` | a person: the token from the tunnel's page in Cloudflare |

A person adds a value from the clipboard, so it never passes through a chat or a file (PowerShell):

```powershell
Get-Clipboard | gcloud secrets versions add algebra-resend-api-key --project algebra-prod-7802b5 --data-file=-
```

## First setup

1. `provision.sh` (already run once). It creates the project, network, service account, KMS key,
   secrets, bucket and VM; it is the record of what exists.
2. Add the Resend key and the Cloudflare tunnel token (above). In Cloudflare, the tunnel's public
   hostname is `api.usealgebra.xyz` → `http://127.0.0.1:8080`.
3. `deploy/gcp/deploy.sh --setup`: builds the current commit, uploads it through the tunnel, checks
   its hashes, installs, starts, and waits for `/readyz`.

## Public HTTPS without Cloudflare (what runs today)

A Cloudflare tunnel needs the domain's nameservers moved to Cloudflare, which waits on the owner's accounts. To be reachable
before that, `public-https.sh` opens ports 80 and 443 to the internet for this VM only (firewall rule `algebra-allow-https`),
installs Debian's Caddy, and gives it a name that resolves to the VM with no DNS record of ours: `34-180-40-140.sslip.io`
(sslip.io answers every `a-b-c-d.sslip.io` with `a.b.c.d`; Google's own `N.N.N.N.bc.googleusercontent.com` can't be used,
its CAA record forbids Let's Encrypt). Caddy gets and renews the certificate and proxies to `127.0.0.1:8080`, which is
what `TRUSTED_PROXY_HOPS=1` already assumes. The address is reserved (`algebra-api-ip`), so the name keeps pointing at the VM
after a stop and start.

What this costs: the API itself faces the internet, with no WAF or DDoS shield in front of it and a name that appears in
certificate-transparency logs. It is acceptable for a Testnet launch and not for real money. `public-https.sh --close`
shuts ports 80 and 443 and stops Caddy; do that once the Cloudflare tunnel carries the traffic. To use a name of your own
first, add an A record for it to the reserved address and run `public-https.sh api.usealgebra.xyz 34-180-40-140.sslip.io`.

Two things this found: the MCP SDK refused every request whose `Host` wasn't loopback while the API listens on `127.0.0.1`
(so `/mcp` answered 403 behind any proxy: fixed, `DisableLocalhostProtection`, `TestMCPOverHTTP_AProxyForwardingItsPublicHostnameIsServed`),
and Caddy 2.6.2's ZeroSSL fallback no longer works, so Let's Encrypt is the only issuer.

## Cutover from Railway (in this order)

The web app and the API are deployed separately, and the web app that comes with this code signs people in
with an emailed code, which the old Railway API does not know. Merging it while `ALGEBRA_API_URL` still
names Railway breaks sign-in on the live site, so the API has to be reachable first.

1. Add the Resend key and the tunnel token (see above), then on the VM `sudo systemctl restart algebra-api cloudflared`.
   `systemctl is-active cloudflared` says `active`.
2. Cloudflare: the tunnel's public hostname `api.usealgebra.xyz` → `http://127.0.0.1:8080`, DNS for the hostname
   (the domain's nameservers at Cloudflare, or a CNAME for `api` alone). Leave Bot Fight Mode off for it and add
   one rate-limit rule on `/api/v1/auth/`.
3. `curl -s https://api.usealgebra.xyz/readyz` answers `{"postgres":"ok","redis":"ok"}`. Then
   `deploy/gcp/monitoring.sh uptime` makes the uptime check.
4. Vercel, production environment: `ALGEBRA_API_URL=https://api.usealgebra.xyz` and `ALGEBRA_EDGE_SECRET` equal to
   the value of `algebra-edge-secret`. Then merge the pull request (the Ignored Build Step builds a main commit
   that touches `frontend/`), or `vercel redeploy --target production`.
5. On www.usealgebra.xyz: ask for a code, sign in, make a pass, run "Test this pass" and one chat request.
6. Only then stop the Railway API and rotate every secret that ever lived there.

When something goes wrong, [docs/RUNBOOKS.md](../../docs/RUNBOOKS.md) has the order to do things in.

| Task | How |
|---|---|
| Deploy the current commit | `deploy/gcp/deploy.sh` (refuses uncommitted changes in `backend/` or `deploy/gcp`; keeps the last binary as `api.prev`) |
| Roll back the binary | on the VM: `sudo cp /opt/algebra/bin/api.prev /opt/algebra/bin/api && sudo systemctl restart algebra-api` (migrations only go forward) |
| Look at logs | `sudo journalctl -u algebra-api -n 100 --no-pager`, or Cloud Logging |
| Health | `curl -s http://127.0.0.1:8080/readyz` on the VM; `https://api.usealgebra.xyz/readyz` from anywhere |
| Which commit runs | `cat /opt/algebra/VERSION` |
| The generated devnet payer's address | on the VM: `sudo -u algebra bash -c 'set -a; . /etc/algebra/api.conf; . /run/algebra/api.env; /opt/algebra/bin/solana-wallet -generated'` |
| Resize the VM | `gcloud compute instances stop algebra-1 ...`, `gcloud compute instances set-machine-type algebra-1 --machine-type e2-standard-2 --zone asia-south1-b ...` (or any other), `... start`: about 3 minutes down, and every service comes back by itself at boot. Turn deletion protection off only to delete it |

## Restore from a backup

The VM cannot read its backups (by design), so a person downloads one and puts it on the VM:

```bash
gcloud storage ls gs://algebra-prod-7802b5-backups/pg/
gcloud storage cp gs://algebra-prod-7802b5-backups/pg/algebra-YYYYMMDDTHHMMSSZ.dump .
gcloud compute scp --tunnel-through-iap algebra-YYYYMMDDTHHMMSSZ.dump algebra-1:/tmp/
# on the VM, with the API stopped:
sudo systemctl stop algebra-api
sudo -u postgres pg_restore --no-owner --clean --if-exists -d algebra /tmp/algebra-YYYYMMDDTHHMMSSZ.dump
sudo systemctl start algebra-api
```

Try it on a scratch database now and then (`createdb algebra_restore_test`, restore into it, count rows
in `users`, drop it). A backup nobody has restored is a hope.

## If something may have leaked

1. Rotate what it touched, newest value wins: `gcloud secrets versions add NAME ...` then
   `sudo systemctl restart algebra-api cloudflared`. The random ones: `openssl rand -hex 32 | gcloud
   secrets versions add NAME --data-file=-`. The web app's `ALGEBRA_EDGE_SECRET` must equal
   `algebra-edge-secret`.
2. **The master key** (`algebra-master-key-wrapped`) seals stored answers, console agent tokens and the
   generated payer key, and derives the receipts' signing key. Changing it makes those unreadable and old
   receipts stop verifying. While only test money is involved, a fresh database with a new master key is
   the clean way; with real money this needs a planned re-seal.
3. Revoke the Resend key in Resend, and the tunnel in Cloudflare (a new token).
4. Read Cloud Audit Logs for the project (Secret Manager, KMS decrypts) for anything you did not do.

## Not covered (be honest)

- One machine: if it fails there is downtime until a new one is made from `provision.sh` and the last
  backup restored. Fine for devnet and pre-launch; real money wants Cloud Run and Cloud SQL.
- A compromised API process can still use what the API may use (the database, the payer key sealed in it).
  KMS and the sandboxing limit what an attacker keeps, not what a live compromise can do while it lasts.
- Mainnet is off. Before real money: the payer is a Cloud KMS key (`docs/SIGNER.md`), and a vault or
  deposit design (docs/PRODUCTION.md) exists.
